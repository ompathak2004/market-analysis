# market-analysis — agent context

Indian-equities intelligence terminal: Bloomberg-style supply-chain intelligence (SPLC), Moneycontrol broker research, a Cerebras-backed intelligence layer (company briefs, broker digests, market brief, filing triage), corporate-aircraft and vessel alt-data, and a Gloomberg-style terminal UI over NSE/BSE data. One Next.js app on Vercel serves the UI, the `/api/v1` read API and the cron jobs. Read this file first; it is the map. Keep it current when you change structure or conventions.

## Jobs and cron

`job_control.mode` (singleton row, enum `job_mode` = `paused|worker` since migration `0011_job_mode_worker_only`, default `paused`) decides whether jobs run; the web app never runs jobs:

- `paused`: the worker holds its lease, consumes nothing and clears its schedules.
- `worker`: `apps/worker` consumes the pg-boss queues (schema `pgboss`) and registers the cron schedules in `src/schedules.ts` (`Asia/Kolkata`, `missed: "once"`).

Worker model: every job type in `packages/jobs/src/contracts.ts` is either a `fanout` (picks stale units and enqueues children in one transaction, recorded as an `ingest_runs` campaign with `children_total/done/failed`) or a `unit` (one company, document or batch). Lanes `control, io, parse, compute, llm, cache` have fixed local concurrency (`LANE_CONCURRENCY`). Each logical unit is a `job_runs` row keyed by `(job_type, unit_key, campaign_id)` with one `job_attempts` row per try. Retries are app-managed with exponential backoff and Retry-After; LLM daily budget and Firecrawl monthly credit exhaustion defer to the next window without spending an attempt; non-retryable errors and exhausted retries go `dead`. A single consumer holds the `worker_leases` row `consumer`; every ledger write is fenced on the lease generation, and a new consumer marks prior running attempts `abandoned`. `ops.reconcile` (15 min) finishes campaigns, abandons overdue runs, raises `ops_alerts`; `ops.digest` emails a daily summary through Resend when `RESEND_API_KEY` and `OPS_DIGEST_TO` are set. With `CLOUDWATCH_METRICS=true` the worker publishes `worker.heartbeat` and `jobs.dead` (namespace `MarketAnalysis`) every minute. SIGTERM drains within 120 s: in-flight work is aborted early enough that a handler settles within the abort grace and still records its attempt before the pg-boss stop timeout; a handler that keeps writing past the grace is left `abandoned` and its job completes, so a pg-boss retry never races it on the next worker. `lease.ts` takes no row lock on `worker_leases` (a FOR SHARE lock would block lease renewal for the rest of the transaction); callers run the lease check as the last statement before commit and ledger writes carry the same generation predicate. `enqueueChildren` upserts `job_runs` and inserts pg-boss jobs in batches so a large fan-out holds its transaction for a handful of statements; children whose singleton key is already queued are dropped with their run row. Derive passes (`pipelines/resume.ts`) walk ids ascending and resume after the last finished id when the deadline cuts them short. `pnpm deploy` in the Dockerfile uses injected workspace packages because its legacy deploy mode re-resolves versions online. The consumer logs the connected role's `statement_timeout`/`lock_timeout` at startup and warns when the role is unbounded.

Production runs the compiled CLI as `node apps/worker/dist/cli.js ...` (no tsx at runtime). Family aliases (`prices`, `moneycontrol`, `broker-reports`, ...; `FAMILY_ALIASES` in `apps/worker/src/cli.ts`) are accepted by `worker:cli run`.

## Data model (Postgres, Drizzle)

Core: `companies` (NSE symbol is the natural key) → `company_aliases`, `company_sync`, `index_constituents`, `indices`, `index_prices_daily`, `prices_daily`, `fundamentals` (annual/quarterly, ₹ Cr), `announcements`, `analyst_calls` (`report_document_id`, `thesis`), `documents` (URL and current-pointer table: `current_revision_id`, `text_parser_version`, `parser_version`, `status`; inline `content` is nullable once the body lives in S3), `signals` (`kind`, `as_of`, `value`, `inputs` jsonb), `ingest_runs`.

Prices (`packages/ingest/src/pipelines/prices.ts`, migration `0005_price_history`): one `price_series_state` row per company (every company, including those without a Yahoo symbol) or index (exactly one owner) holds the desired five-year window (ending at the last session before today), `verified_through`, `adjustment_generation`, `action_hash`, `quality_status` (pending|partial|complete|exception|rebuild_required), `exception_reason` (no_yahoo_symbol|not_in_nse_equity_list|isin_mismatch|identity_mismatch|listing_source_unavailable; all but the last are never fetched) and `detail` (why the last write was incomplete or refused). `price_manifests` / `price_manifest_companies` (migration `0006`) freeze each backfill's company list, units and exceptions. `prices_daily` / `index_prices_daily` rows carry `source`, `source_symbol`, `parser_version`, `adjustment_generation`, `is_final` (the bar's IST day has passed) and, for equities, `adjustment_status`. `trading_sessions` (exchange `NSE`) is the expected-session calendar, currently derived from ^NSEI dates. `price_gaps` stores coalesced missing ranges with a reason, `status` open|exempt|resolved and exponential `next_check_at`. `corporate_actions` (splits, dividends, keyed by `event_key`) and `market_symbols` (provider symbol validity) come from the Yahoo chart events and the `market-indices.ts` / universe registry. Rules: OHLC is split-adjusted, `adj_close` is split+dividend adjusted, index rows are price-return levels (`PRICE_BASIS` in `@ma/db`). A window write refuses a symbol the series does not own and a generation that is not current; a new or corrected corporate action marks the series `rebuild_required` instead of rescaling rows, and `prices.rebuild` refetches the whole window and moves every row to the next generation in one transaction, or writes nothing (`rebuild_incomplete`) when the refetch misses expected sessions. A window result keeps coverage (`status`) and the source's answer (`sourceStatus` ok|not_found|invalid_response|identity_mismatch) apart, and `windowOutcome` maps both to complete|retry|defer|exception|skipped: unexplained sessions (`incomplete`), an empty or invalid source response, or an empty rebuild throw `price_incomplete` (retryable) after committing; `calendar_pending` (an equity window the calendar does not span yet) throws `DeferredError`; `identity_mismatch` becomes a durable series exception and succeeds. Repair-mode windows only throw to defer. `priceSynced` (complete and through the latest session) gates every `company_sync` write for prices. Backfill priorities: calendar index 3, indices 2, rebuild 1, daily 0, equity -1, carried in the envelope across retries. Replays compare floats with a 1e-5 relative tolerance (Yahoo recomputes `adj_close` per request). Readers (`loadCloses` in `@ma/intel`) use only final rows on the current generation with non-null `adj_close`; the web `priceSnapshot` serves the current generation with a per-bar `final` flag and its metadata from one statement.

Documents and evidence (migration `0007_documents_evidence`, `packages/db/src/schema/evidence.ts`): `DocumentStore.fetch` writes one `document_revisions` row per distinct body (`content_sha256`, `text_parser_version`, `text_s3_key` → gzip text in the object store, `text_bytes`, `page_map` for PDFs, `raw_unavailable`), records `storage_objects`, and sets `documents.current_revision_id`; `text(revision)` hydrates inline-or-S3, `textOf(documentId)` is the `IntelContext.docs` reader. `evidence_spans` (`document_revision_id`, UTF-16 `start_offset/end_offset` into the immutable revision text, `quote`, `page`, `locator`) are the only citation primitive for SPLC and INFL. Jobs: `documents.snapshot` → `documents.revision` (snapshot legacy inline bodies as revision 1), `documents.release` (null the inline body once the S3 object is verified and no extraction is pending), `documents.gc` (unreferenced `storage_objects` older than 7 d). Blob writes always happen before the DB transaction.

Supply chain (SPLC v3, migration `0008_splc_v3`, `packages/db/src/schema/splc.ts`): `counterparties` (listed → `company_id`, else private|government|foreign|group) → `counterparty_identifiers`, `counterparty_aliases` (`exact_case` for short symbols), `company_group_memberships`; every read of a document revision is a `relationship_extractions` row keyed by `(document_revision_id, extractor_family, extractor_version, inputs_hash)` whose output is `relationship_observations` (`value_basis` revenue_share|purchase_share|annual_flow|contract_total|unknown, `cost_bucket`, `cue_class`, `status` pending|auto|confirmed|rejected|blocked|superseded) → `relationship_observation_evidence` → `evidence_spans`; observations materialize into `relationships` edges keyed by `edge_key` (`status` active|expired|superseded|blocked|legacy, `extractor_family/version`, `graph_revision`, `last_disclosed_at`, `valid_to` = last disclosure + 4 y) and `company_graph_state`; `relationship_sources` tracks which filings were read per family; `relationship_estimates` are unique per `(relationship_id, as_of, model_version, value_basis)` and `contract_total` never sums into annual flows; `relationship_priors`, `relationship_financial_facts`, `relationship_blocks`, `relationship_reviews`. Pre-v3 rows are `status='legacy'` and never served. Reviewers decide through `review_relationship()` (SECURITY DEFINER, `ma_web` executes) behind `POST /api/v1/admin/relationships/reviews` and `/admin/review`. Precision gate (migration `0012_relationship_precision_samples`): `relationship_precision_samples` (unique `name`, optional `extractor_family`, `size`, `seed`) → `relationship_precision_sample_items` (`position`) freeze a seeded draw of auto, confirmed and rejected observations behind active edges; an item's decision is its latest `relationship_reviews` row, else its confirmed/rejected/blocked status; `/admin/review?sample=<name>` queues the undecided items in draw order and `GET /api/v1/admin/relationships/precision?sample=<name>` passes once every item is decided and the Wilson 95 % lower bound on confirmed/decided reaches 0.9. Jobs: `relationships.counterparties`, `relationships.fanout/extract` (`force` for rebuilds), `relationships.rebuild` (one-off campaign), `relationships.sample` (manual, `{name, size?, family?, seed?}`, idempotent by name), `orders.fanout/extract` (order-win filings, `ORDER_RELATIONSHIP_EXTRACTOR_VERSION`). LLM extraction (`packages/intel/src/relationships`): extractor versions ≥ `LLM_EXTRACTOR_VERSION_BASE` (100) are LLM reads, and `writeExtraction` only replaces pending/auto observations of the same kind (regex or LLM); LLM adapters leave `relationship_sources.read_*` to the regex pass (except rating rationales and presentations, which only the LLM reads) and rely on the `relationship_extractions` ledger for pending work. Jobs `relationships.llm` (plans documents within the remaining `relationships` budget) → `relationships.llm.extract` (lane `llm`, key `source:document:revision`), `relationships.priors`, `ratings.fanout/sync` (family `rating_rationale`), `presentations.fanout/sync` (family `presentation`, gated by `SPLC_PRESENTATIONS_PILOT`).

Announcements (migration `0009_announcement_policy`): `announcements` carry `category_key`, `retention_class` forever|five_years|noise|review_hold, `retain_until`, `policy_version` (`ANNOUNCEMENT_POLICY_VERSION` in `packages/ingest/src/announcements/policy.ts`); `noise` is dropped at ingest; `announcement_holds` pins rows cited by evidence; `maintenance.announcements` is the one-off backup → classify → delete → reindex campaign and `maintenance.prune` applies the retention table in `docs/ops.md`.

Research (Moneycontrol): `shareholding`, `analyst_ratings`, `consensus_history`, `earnings_estimates`, `price_targets`, `earnings_surprises`, `company_facts`.

Intelligence: `insights` (`kind` company_brief|broker_digest|market_brief|announcement_triage, `inputs_hash`, `superseded_at`, `model_version`, validated JSON `output`), `llm_usage`.

Alt-data: `corporate_aircraft` → `corporate_aircraft_companies`, `aircraft_positions`, `aircraft_flights`; `facilities` → `facility_companies`; `vessels`, `vessel_positions`, `vessel_calls`, `chokepoint_transits`, `vessel_fleet`; `altdata_events`, `altdata_coverage`.

Influence (INFL, migration `0010_influence`, `packages/db/src/schema/influence.ts`): `persons` (DIN-keyed) → `person_aliases`, `person_identifiers`; `graph_nodes` (exactly one of person, company, counterparty, sector, policy event or party); typed facts `person_roles`, `ownership`, `related_party_transactions`, `political_roles`, `affidavit_interests`, `electoral_bond_rows`, `political_donations`, `policy_events` → `policy_event_tags`; `influence_edges` (one fact FK, `confidence`, `status` pending|confirmed|rejected, `version`) → `influence_edge_evidence` (evidence spans), `influence_reviews`; `influence_extractions` (`input_hash` per filing read), `influence_events` → `influence_event_edges`, `influence_coverage`. Readers use the `influence_edges_confirmed` and `graph_node_labels` views; operators decide pending edges only through `review_influence_edge(edge_id, decision, reviewer, note, expected_version)`. Jobs: `influence.governance[.fanout]`, `influence.rpt[.fanout]`, `influence.perimeter[.fanout]` (weekly, Sunday IST). Web: `GET /api/v1/companies/:symbol/influence` and the `INFL` tab (key `0`).

Political and policy influence (`packages/intel/src/influence/{politics,policy,events,politics-sync,policy-sync}.ts`, sources in `packages/ingest/src/sources/{parliament,myneta,eci-bonds,pib,prs,egazette}.ts`, ministry/industry → sector map in `packages/ingest/src/data/policy-sectors.ts`): jobs `influence.parliament` (weekly), `influence.affidavits` → `influence.affidavit` (monthly), `influence.bonds` (manual, SBI PDF URLs in the payload), `influence.sectors` (weekly), `influence.policy.pib` (hourly), `influence.policy.prs` and `influence.policy.gazette` (daily, gazette PDF URLs in the payload) and `influence.policy.tag` → `influence.policy.tag.event` (hourly, LLM budget class `influence`, only when no ministry rule applies). Political paths in the INFL pane come from `confirmedPaths` and require every hop to be confirmed with evidence; `donated_to` edges stay listed after `valid_to`. Pending edges are reviewed at `/admin/review` through `GET`/`POST /api/v1/admin/influence/reviews` (`{edgeId, decision, expectedVersion, note}`), which calls `review_influence_edge` and invalidates the influence cache of every company within three confirmed hops of the edge, or operating in a sector it touches.

Signal kinds: `customer_concentration_pct`, `top{N}_customers_pct`, `customer_momentum_{1m,2m,3m}`, `supplier_momentum_{1m,2m,3m}`, `customer_hhi`, `distress_score`, `travel_*` and `logistics_*` (`packages/intel/src/altdata/types.ts`).

## Conventions

- No comments unless the *why* is non-obvious; no dead code; no TODO markers — put open work in `docs/plan.md`.
- Biome for lint/format (`pnpm lint:fix`). `exactOptionalPropertyTypes` is on: use `?? null`, not `undefined`, for nullable columns.
- Every external fetch goes through `IngestContext.http` (per-host token buckets in `HOST_LIMITS`) or `DocumentStore`; never `fetch` directly in pipelines. Firecrawl calls go through the monthly credit budget.
- Parsers carry a `*_PARSER_VERSION`/`*_EXTRACTOR_VERSION`; bump it when output changes so stale documents re-parse.
- Models carry a `*_MODEL_VERSION`; estimates, signals and insights are keyed by it so old rows stay comparable. LLM outputs are validated against the zod schemas in `packages/intel/src/insights`; every claim cites an evidence id from the prompt inputs, and a brief is regenerated only when its `inputs_hash` changes.
- Every LLM call names its `budgetClass` (`relationships`, `insights` (default) or `influence`). Each class has its own daily cap inside `LLM_DAILY_TOKEN_BUDGET` (200k, 500k and 100k of 800k, overridable with `LLM_BUDGET_RELATIONSHIPS/INSIGHTS/INFLUENCE`), so one consumer cannot starve the others; `LlmBudget.remainingToday(class)` is the lower of the class and the total remainder. Graph-derived signal readers filter with `activeSignalVersionClause` from `@ma/intel` instead of taking the highest `model_version`.
- Read models live in `apps/web/src/server/queries/*.ts` (`core`, `research`, `insights`, `altdata`, `screens`), are cached through `ctx.api` with explicit `ttlMs/staleMs`, and are shared by the route handlers and the server components; jobs invalidate prefixes after writes. Web code imports workspace packages by name and local modules without a `.js` suffix.
- Web UI: routes in `src/app` (`/`, `/c/[symbol]/[tab]`, `/signals`, `/movers`, `/help`) compose panes from `src/components/panes/**`, which call read models through `attempt()` so one failing pane renders `DATA UNAVAILABLE` instead of failing the page. Primitives live in `src/components/ui`, shell chrome in `src/components/shell`, keyboard handling in `src/lib/keymap`. Styles are plain CSS in `src/styles` (`tokens.css` holds every colour/size; panes place themselves with the `--area` custom property into `grid.css` layouts). Function codes: DES, GP, FA, ANR, SPLC, NEWS, JET, SHIP, INTL, INFL (key `0`). Admin pages `/admin/login` and `/admin/review` (`?sample=<name>` reviews a precision sample) need `ADMIN_API_KEY` (signed `ma_admin` cookie or `x-admin-key`). Every page must fit 1440×900 with no document scroll; panes scroll internally with the custom scrollbar.
- Commits: conventional (`feat(scope): …`), small, one concern each. `.env` is gitignored (GitHub push protection rejects the Aiven password); `.env.example` is the contract.
